# Волна 2. Хуки — дизайн

Источник истины — секция 15 общей спеки
(`docs/superpowers/specs/2026-08-08-context-repo-plugin-design.md`, строки
1747–1939). Этот документ не пересказывает её, а решает то, что она оставила
реализации, и называет каждое решение решением.

Критерии выхода — `docs/roadmap.md`, «Волна 2».

## Что волна потребляет

Всё общее принадлежит волне 1 и здесь только читается:

| откуда | что |
|---|---|
| `scripts/zones.py` | `ZONES`, `zone_of()`, `TRANSIENT`, `ADD_ONLY`, `READ_ONLY`, `DENY_PATTERNS` |
| `scripts/findings.py` | `EXIT_OK`, `EXIT_VIOLATION`, `EXIT_TOOL_FAILED`, классы находок, `Report.render()` |
| `scripts/paths.py` | признак пути, `escapes_root()` |
| `scripts/check_links.py`, `scripts/check_frontmatter.py` | `scan(root, today=None) -> Report` |

Своей таблицы зон волна не заводит: `tests/test_zones.py::TestSingleDefinition`
падает на копии модуля где угодно в пакете, включая `hooks/`.

## Архитектура: один вход

```
hooks.json  →  hook.sh <event>  →  hook.py <event>
               ~10 строк            вся логика
```

**Почему шим на shell, а не прямой вызов python.** Единственная работа
`hook.sh` — гарантировать, что «не смог» не выглядит как «разрешил молча».
Если `python3` отсутствует или падает при импорте, shell печатает одну видимую
строку с причиной и выходит нулём. Без этого слоя отказ интерпретатора
неотличим от успеха: у изученного аналога хук возвращал 1 на каждом вызове
из-за отсутствия `flock` на macOS, это читалось как «занято», и автокоммиты
молча отключились у всех пользователей macOS.

**Почему `hook.py` импортирует гейты, а не зовёт их подпроцессом.** Гейты —
модули того же пакета, ноль зависимостей, импорт дешевле процесса, и разбор
stdin-JSON остаётся один на все события. Контракт «запретил ≠ не смог» от
этого не страдает: сбой импорта ловит `hook.sh`, сбой внутри логики ловит
`hook.py` собственным `try` вокруг всего тела.

*Решение агента.* Альтернатива — звать `python3 scripts/check_links.py`
подпроцессом на каждое событие. Отвергнута: три процесса на запись файла
против одного импорта, и второй разбор JSON.

## Контракт кодов возврата

| что случилось | код | что печатается |
|---|---|---|
| нарушение | 2 | файл, строка, что чинить — в stderr |
| всё в порядке | 0 | ничего |
| гейт не смог выполниться | 0 | **видимая строка** «гейт не выполнился: причина» |

Запрещено дословно: `2>/dev/null`, `|| true`, логирование отказа в файл вместо
экрана. Проверка на это — тест, а не соглашение: гейт пакета уже ловит
`absolute-path` и `relative-path-in-skill`; для хуков добавляется тест,
читающий `hooks/*.sh` на предмет этих трёх шаблонов.

## Пять моментов

### 1. `SessionStart`

Считает сводку из git и файловой системы, печатает в stdout — всё, что хук
пишет в stdout, попадает в контекст сессии. **На диск не пишет** (секция 11):
хук, перезаписывающий файл на каждом старте, делает дерево грязным, а грязное
дерево по решению секции 8 означает «здесь работал человек», и ветка
«пусто → тишина» не наступила бы уже никогда.

```
последний чекпоинт: 2026-08-02, 14 файлов
незакоммиченного: нет
inbox: 12, старшему 9 дней
```

Затем спрашивает git о несохранённом. Нет — молчит. Есть — прогоняет по
изменённым файлам гейты, зелёное сохраняет чекпоинт-коммитом, красное
показывает и не коммитит.

### 2. `PreToolUse`, ветка записи

Матчер `Edit|NotebookEdit|Write`. Два разных исхода:

- путь после нормализации вне корня репозитория → **блок**, код 2, в тексте
  названа граница;
- путь нарушает конвенцию зоны → **предупреждение**, код 0, текст в stderr.

`knowledge/*/**` здесь не проверяется: он закрыт раньше и статически, через
`permissions.deny` в `settings.json` целевого репозитория. Дублировать статику
динамикой — заводить второй источник истины.

### 3. `PostToolUse`, ветка записи

Тот же матчер. Прогоняет оба гейта и **оставляет находки только по тому файлу,
который только что записан**. Фильтр — по `Finding.path`, не отдельный режим
гейта: индекс ссылок всё равно строится по всему дереву, иначе `unresolved`
неотличим от «цель есть, но её не просканировали».

Здесь же дописывается путь в список файлов хода.

### 4. `PreToolUse`, ветка Bash

Матчер `Bash`. Сканер команды: посимвольный разбор кавычек, сегментное
сопоставление путей (`journal/` совпадает, `journaling/` нет). Блокирует `mv`,
`git mv` и прямую запись в дерево контента в обход инструментов; в тексте
называет скрипт, которым это делается правильно.

**Явный список неперехватываемого** — часть поставки, а не оговорка:
удаление через python, `mv` в `/tmp`, `eval`. Записанный остаточный риск
отличает бэкстоп от притворной песочницы. Это защита от случайности,
не от намерения, и так и написано в тексте отказа.

### 5. `Stop`

**Синхронно.** Асинхронный хук не может задержать завершение хода, а без
задержки требование «красный ход не может закончиться» невыполнимо.

`stop_hook_active` обязателен: второй раз подряд не блокируем, иначе ход
не заканчивается никогда.

Проверяет всё незакоммиченное, реакция разная по происхождению файла:

| что сломано | реакция |
|---|---|
| файл из списка хода | **блок**, ход не заканчивается |
| файл, правленный человеком снаружи | сообщение и предложение починить |

Иначе человек, сломавший ссылку в Obsidian, заблокировал бы работу агента.

Чекпоинт: `git add` **только по путям, прошедшим гейты**, никогда `-A`.
`git add -A` заберёт сдвиги указателей сабмодулей `knowledge/` и параллельные
правки человека в Obsidian.

## Граница рабочего каталога

> Всё, что плагин меняет, лежит внутри корня репозитория. Наружу он не пишет
> никогда.

Корень — тот, что нашёл поиск маркера `.twinkle-repo-builder` вверх по дереву,
не выше git-корня (секция 22).

Проверка **нормализует путь до сравнения**: `..`, симлинк и абсолютный путь
дают один и тот же ответ. Сравнение по префиксу строки без нормализации
ловится собственным `..` и потому не годится — это ровно та ошибка, которую
`escapes_root()` волны 1 уже один раз пережил.

Чтение не ограничивается и ограничено быть не может: код плагина живёт вне
репозитория, скиллы зовут его через `${CLAUDE_PLUGIN_ROOT}`, запрет отключил
бы плагин целиком. Ограничение — на **изменение** и на **ссылки в содержимом**.

## Список файлов хода

Нужен `Stop`-хуку, чтобы отличить «сломал агент в этом ходе» от «сломал
человек в Obsidian». Живёт между вызовами инструментов, умирает вместе
с сессией.

**Решение агента: файл в `.git/`, имя несёт `session_id`.**

Три требования сталкиваются: файл должен пережить несколько вызовов
инструментов (значит, на диске), не может лежать вне корня (незыблемое №6)
и не имеет права делать дерево грязным (иначе ломается разводка «незакоммиченное
= работал человек», на которой стоят и `SessionStart`, и `Stop`).

`.git/` — единственное место внутри корня, которое git по построению
не показывает в `git status`. Альтернатива — `tmp/` с записью в `.gitignore`;
отвергнута, потому что `tmp/` это зона с содержимым автора, и служебный файл
плагина в ней виден человеку в Obsidian и выглядит как его файл.

Остаточный риск назван: `.git/` чистится сборщиком мусора git не всегда
предсказуемо. Файл не хранит ничего, кроме списка путей текущего хода, и его
потеря деградирует `Stop` до поведения «считать все незакоммиченные файлы
чужими» — то есть до сообщения вместо блока. Это ослабление, а не поломка,
и оно проверяется тестом.

## Что волна намеренно не делает

**Не заводит тип хука `prompt`.** Спека называет исход «спросить автора»
кандидатом и честно пишет, что деталей в документации мало. Закрытое множество
типов хуков в проверке пакета — `{"command"}`. Незыблемое №3: механизм не
заводится, пока не предъявлена наблюдённая поломка, которую он чинит. Пока
её нет, переписывание `core`/`areas` остаётся предупреждением.

**Не решает порядок исполнения хуков при нескольких плагинах.** Не
документирован, наблюдений нет, ни одно правило волны на него не опирается.

## Фикстуры и проверка

Каждый хук прогоняется **настоящим подпроцессом**, никогда вызовом логики
напрямую: тест, зовущий функцию, не проверяет ни `hooks.json`, ни шим, ни
код возврата — то есть ровно то, что ломается на практике. Тест утверждает
**и код возврата, и сообщение**.

Фикстура — временный git-репозиторий, собираемый в тесте: восемь зон, маркер
рецепта, пара файлов. Ноль зависимостей: `git init` через `subprocess`.

## Открытый вопрос

Матчер `Edit|NotebookEdit|Write` покрывает запись инструментами. Запись через
`Bash` (`cat > file`, `tee`) ловится сканером команд ветки 4. Комбинация
«python-скрипт, запущенный через Bash, пишет в дерево» не ловится ничем и
названа в списке неперехватываемого. Это осознанный остаточный риск, а не
дыра, которую забыли.
